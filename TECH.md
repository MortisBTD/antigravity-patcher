# Как устроен патч

Заметки по версии Antigravity 2.24.0. Всё, что ниже, проверено на живой установке.

## Где сидит блокировка

Antigravity — это тонкая Electron-оболочка плюс Go-сервер `language_server.exe`.
Оболочка (`resources\app.asar`) умеет только запускать сервер и открывать окно;
сам интерфейс отдаёт сервер с локального порта (`Serving UI bundle from embedded assets`).

Экран «not currently available in your location» приходит не из клиента, а с бэкенда.
Языковой сервер дергает `POST https://cloudcode-pa.googleapis.com/v1internal:loadCodeAssist`
с телом `{"metadata":{"ideType":"ANTIGRAVITY"}}` и своим Bearer-токеном. Ответ содержит
`ineligibleTiers` с `reasonCode: "UNSUPPORTED_LOCATION"` и текстом про локацию.
`fetchUserInfo` там же отдаёт `regionCode: "RU"`.

Важное: ответы байт-в-байт одинаковые и с российского IP, и через нидерландский выход.
То есть это флаг на аккаунте, а не проверка IP. Один VPN проблему не решает — именно
поэтому появился этот патч.

## Что правится

Интерфейс лежит внутри `language_server.exe` в виде zip-архива:

```
EOCD             0x8de2be6
записей в CD     304
база архива      0x8a1d470
main.js          local header 0x8a3d1eb, deflate, csize 2949946, usize 10095222
данные main.js   0x8a3d210
```

Второй архив в файле (598 записей, база `0x381c300`) интерфейс не содержит — его трогать
не нужно.

В `main.js` правятся два места.

**1. Стартовая проверка статуса.** Опрос при старте пускает дальше только при валидной
авторизации:

```js
if(k?.hasValidAuth){if(g!=="signedIn"){
```

становится

```js
if(k?.hasValidAuth||k?.ineligible){if(g!=="signedIn"){
```

**2. Обработчик ошибки входа.** Функция `Qz` разбирает `failureDetails` и на
`case==="ineligible"` шлёт в стейт-машину `SET_INELIGIBLE`, что уводит на экран
с блокировкой:

```js
c?.case==="ineligible"?a._authActor.send({type:"SET_INELIGIBLE",message:b,verificationUrl:c.value.verificationUrl||
void 0}):
```

Ветка заменяется на событие успеха:

```js
c?.case==="ineligible"?a._authActor.send({type:"AUTH_SUCCESS",tokenInfo:{accessToken:""},scopes:[],project:"aicode-consumers"}):
```

`AUTH_SUCCESS` в машине состояний ведёт в `signedIn` и заполняет `tokenInfo`, `project`,
`grantedScopes` (по умолчанию `[]`) — остальное подставляется дефолтами. Токен там пустой
намеренно: реальный токен сервер уже получил, экрану он не нужен.

Якорь второй замены содержит перевод строки перед `void 0` — бандл перенесён автором
по этой границе. Однострочный шаблон не совпадёт ни разу.

## Как правится архив

1. Найти все `PK\x05\x06`, для каждого посчитать базу `eocd - cdsize - cdoff` и проверить,
   что по `base + cdoff` лежит `PK\x01\x02`. Так отсеиваются ложные сигнатуры.
2. Выбрать архив, в центральной директории которого есть `main.js`.
3. Распаковать entry (raw deflate, `-15`), проверить usize и CRC32 (`2451599952` для 2.24.0).
4. Применить замены, сжать девятым уровнем.

   Исходный бандл сжат слабее: `2949946` против `2939141` после пересжатия. Запас ~10.8 КБ,
   поэтому длина патченного блока всё равно меньше исходной и сдвигать офсеты не нужно.

5. Записать блок по месту, добить нулями до исходного `csize`, обновить CRC и размеры
   в локальном заголовке (`lho + 14`) и в записи центральной директории (`entry + 16`).
6. Перечитать файл, распаковать заново, сверить CRC и что размер файла не изменился.

Пункт 6 не формальность: если промахнуться мимо записи в CD (например, прибавить базу
к уже абсолютному офсету), файл молча вырастет на сотню мегабайт нулей, интерфейс
перестанет проходить проверку CRC, и приложение покажет пустой экран.

## Как проверялось

Окно Electron на этой машине не отдаётся ни через PrintWindow, ни через захват региона —
на выходе чёрный кадр (DirectComposition). Поэтому проверка шла через DevTools-протокол:
у процесса, который слушает порт, брался `http://127.0.0.1:<port>/json/list`, оттуда
`webSocketDebuggerUrl`, и через `Runtime.evaluate` читался `document.body.innerText`.

До патча в тексте был `ineligible`, после — обычный рабочий интерфейс: меню, Projects,
Conversations, поле ввода, выбор модели. Ни одного упоминания локации.

## Что ломается

* Автообновление заменяет `language_server.exe` целиком — патч исчезает, надо применять заново.
* При смене версии меняются офсеты и CRC в архиве. Патчер на это ругается
  («сборка нестандартная») и ничего не пишет.
* VPN всё равно нужен: патч убирает только экран, а не сетевую проверку на стороне сервера.
